Les questions que les responsables de mosquées nous posent le plus souvent — avec des réponses honnêtes.

Gratuité & modèle économique

Oui, le logiciel est gratuit et le restera. Nidham n'est pas un SaaS commercial. Il n'y a pas d'abonnement mensuel, pas de version "premium" cachée, pas de freemium.

Ce qui peut avoir un coût, c'est uniquement l'infrastructure que vous choisissez :

  • Mode Pi local : achat unique d'un Raspberry Pi (35–80€), propriété de la mosquée. Ensuite, 0€/mois pour toujours.
  • Mode BYOD Supabase : compte gratuit jusqu'à 500 MB (suffisant pour 500–800 familles). Au-delà : 25$/mois, payé directement à Supabase.

Nous ne sommes ni intermédiaires ni revendeurs. Vous payez Supabase ou le matériel — pas Nidham.

Le développement est 100% bénévole, réalisé sur le temps libre par conviction.

Les seuls frais réels sont l'infrastructure du projet lui-même : le domaine nidham.fr (18,70€ jusqu'en 2029) et l'hébergement du site (0€ sur GitHub Pages).

Des soutiens financiers sont acceptés pour couvrir ces coûts et éventuellement financer du matériel pour les mosquées qui n'ont pas les moyens. Tout est détaillé sur la page Transparence.

C'est notre engagement. Nidham est pensé comme un waqf numérique — une contribution durable à la communauté, pas un produit à monétiser.

Si le projet grandit, on cherchera des bénévoles, des contributeurs open source, ou des partenariats institutionnels — pas un modèle par abonnement. Les mosquées ont des budgets serrés et méritent des outils sérieux sans friction financière.

Données & vie privée

Personne d'autre que vous. C'est le cœur du modèle BYOD (Bring Your Own Database).

  • Mode Pi local : les données sont stockées sur votre propre serveur dans vos locaux. Elles ne partent nulle part. Même si internet tombe en panne, votre outil continue de fonctionner.
  • Mode BYOD Supabase : vous créez vous-même votre compte Supabase. Nidham se connecte à votre base avec vos propres identifiants — nous n'avons aucun accès, aucune visibilité, aucune copie.

Nidham ne centralise pas de données. Il n'y a pas de "serveur Nidham" qui connaît vos adhérents.

Le modèle BYOD est structurellement favorable au RGPD : les données restent chez vous, sous votre contrôle, sans tiers intermédiaire.

En tant qu'association, vous êtes le responsable de traitement. Nidham est un outil que vous utilisez — à vous de déclarer les traitements si nécessaire (fichier adhérents, trésorerie, etc.) selon vos obligations légales.

L'outil ne collecte aucune donnée à des fins commerciales, ne revend rien, et ne croise pas vos données avec d'autres.

Oui, toujours. Vos données vous appartiennent.

  • Export CSV depuis l'interface pour les adhérents, les paiements, les entrées comptables.
  • Accès direct à votre base de données Supabase (PostgreSQL) ou fichiers SQLite sur le Pi — vous pouvez sauvegarder comme vous voulez.

Pas de lock-in. Si vous décidez de partir ou de changer d'outil, vous emportez tout.

Technique & déploiement

Non. L'interface quotidienne est une application web simple. Pas de ligne de code, pas de terminal, pas de configuration à faire.

L'installation initiale (Pi ou BYOD) est accompagnée par notre équipe. On s'occupe de tout : installation, configuration, formation du bureau sur les fonctions principales.

Une fois en place, l'outil fonctionne comme n'importe quelle appli web — depuis un téléphone, une tablette ou un PC.

Les deux modes font tourner exactement le même logiciel. La différence est où sont stockées vos données :

  • 💻 Pi local : un petit serveur dans vos locaux (Raspberry Pi, ~60€). Données chez vous, aucune dépendance internet pour l'usage quotidien, accès en réseau local. Idéal pour les mosquées avec une salle informatique ou un local sécurisé.
  • ☁️ BYOD Supabase : votre base de données est dans le cloud, sur votre compte Supabase gratuit. Accessible de partout avec internet. Aucun matériel à acheter ni à maintenir. Idéal pour les petites associations sans local dédié.
  • 🔃 Hybride : Pi pour le stockage principal + sauvegarde automatique sur Supabase. Le meilleur des deux mondes.

Oui. Les données sont exportables et importables entre les deux modes. Si vous commencez en BYOD et souhaitez passer en Pi (ou inversement), on peut faire la migration avec vous.

Il n'y a pas de pénalité, pas de frais de migration. C'est votre projet, votre infrastructure.

L'interface web est responsive et utilisable sur mobile. Pour un usage quotidien confortable (saisie de cotisations, consultation de fiches), un smartphone suffit.

Une application mobile native (iOS & Android) est prévue dans la roadmap — pour encore plus de fluidité et la possibilité de travailler hors ligne.

Cadre légal & institutionnel

Oui. Nidham est conçu pour les associations françaises, qui fonctionnent majoritairement sous loi 1901 (association) ou loi 1905 (culte).

La gestion des cotisations, la trésorerie et les rapports sont pensés pour répondre aux obligations de ces statuts : assemblée générale annuelle, compte de résultat, suivi des adhérents.

L'outil ne génère pas de documents comptables certifiés (bilan officiel pour un commissaire aux comptes) — il est pensé comme outil de gestion interne, pas comme logiciel de comptabilité agréé.

C'est une question légitime. Voici les garanties :

  • Le code est open source sur GitHub. Si le projet s'arrête, le code reste accessible — n'importe qui peut le reprendre, le forker, le faire évoluer.
  • Vos données vous appartiennent — elles sont dans votre propre base (Pi ou Supabase). Vous pouvez les exporter à tout moment au format CSV, sans dépendre de nous.
  • Aucune dépendance à un service Nidham : l'outil ne pointe pas vers nos serveurs pour fonctionner. Pas de clé d'activation, pas d'abonnement, pas de central.

En résumé : si demain le projet s'arrête, votre installation continue de fonctionner indéfiniment, et vos données sont récupérables.
